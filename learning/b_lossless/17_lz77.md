# Chapter 17: LZ77

## History

Published by Abraham Lempel and Jacob Ziv in 1977. Foundation of most modern compressors.

---

## The Sliding Window

LZ77 uses two buffers:

```
[-------- Search Buffer --------][-- Lookahead --]
         (already seen)            (to encode)

Example:
"the quick brown fox" | "jumps over"
       ↑ Search         ↑ Lookahead
```

**Search buffer**: Recently processed data (the dictionary)
**Lookahead buffer**: Data we're about to encode

---

## The Algorithm

For each position:

1. Find longest match of lookahead in search buffer
2. Output tuple: (offset, length, next_char)
3. Advance window by (length + 1) positions

### The Output Tuple

```
(offset, length, next_char)

offset: How far back the match starts
length: How many characters match
next_char: First character after the match
```

---

## Step-by-Step Example

### Input

```
"AABCBBABC"
```

### Window Sizes

Search buffer: 6 characters
Lookahead: 4 characters

### Trace

```
Step 1:
Search: [      ]  Lookahead: [AABC]
No match possible (search is empty)
Output: (0, 0, 'A')
Advance 1

Step 2:
Search: [A     ]  Lookahead: [ABCB]
'A' matches at offset 1, length 1
Output: (1, 1, 'B')
Advance 2

Step 3:
Search: [AAB   ]  Lookahead: [CBBA]
No match for 'C'
Output: (0, 0, 'C')
Advance 1

Step 4:
Search: [AABC  ]  Lookahead: [BBAB]
'B' matches at offset 1, length 1
Output: (1, 1, 'B')
Advance 2

Step 5:
Search: [BCBBA ]  Lookahead: [ABC ]
'AB' matches... but where?
'A' at offset 5, but 'AB' at offset 4
Match: offset=4, length=2
Output: (4, 2, 'C')
Advance 3

Done!
```

### Encoded Output

```
(0,0,'A') (1,1,'B') (0,0,'C') (1,1,'B') (4,2,'C')
```

---

## Decoding

Simple: replay the operations.

```
(0,0,'A') → Output 'A'        Buffer: "A"
(1,1,'B') → Copy 1 back, len 1 → 'A'
            Output 'A' + 'B'  Buffer: "AAB"
(0,0,'C') → Output 'C'        Buffer: "AABC"
(1,1,'B') → Copy 1 back, len 1 → 'B'
            Output 'B' + 'B'  Buffer: "AABCBB"
(4,2,'C') → Copy 4 back, len 2 → 'AB'
            Output 'AB' + 'C' Buffer: "AABCBBABC"
```

Result: "AABCBBABC" ✓

## Overlapping Matches

A match can extend into itself!

```
Input: "ABABABAB"

Search: [AB    ]  Lookahead: [ABAB]

Match 'AB' at offset 2... but we need length 4!

The trick: Copy byte by byte
  Copy position: 2 back from current
  Copy byte 1: 'A' (from search buffer)
  Copy byte 2: 'B' (from search buffer)
  Copy byte 3: 'A' (just copied!)
  Copy byte 4: 'B' (just copied!)

This produces "ABAB" from just "AB"!
```

This is how LZ77 efficiently encodes repeated patterns.

---

## Encoding Format

Original LZ77 tuples are wasteful when no match exists.

```
No match: (0, 0, 'X')  ← Uses full tuple for 1 byte
```

Improvements:
- **LZSS**: Use flag bit to distinguish match vs literal
- **DEFLATE**: Interleave literals and matches differently

---

## Finding Matches

### Naive Approach

```
for each position in search buffer:
    compare with lookahead
    track longest match

Time: O(search_size × lookahead_size)
```

Very slow for large windows.

### Hash Chain

```
1. Hash first 3 bytes of lookahead
2. Look up hash → get list of positions with same hash
3. Check each position for actual match
4. Update hash table with current position

Time: O(chain_length × lookahead_size)
```

DEFLATE uses hash chains with max chain length.

### Suffix Tree/Array

```
Build suffix tree of entire input
Query: O(match_length) time

Time: O(n) to build, O(m) per query
Space: O(n) — often too much for streaming
```

Best compression, highest memory.

## Pseudocode

### Encoder

```
function lz77_encode(input):
    output = []
    pos = 0

    while pos < length(input):
        match = find_longest_match(input, pos)

        if match.length > 0:
            output.append((match.offset, match.length, input[pos + match.length]))
            pos += match.length + 1
        else:
            output.append((0, 0, input[pos]))
            pos += 1

    return output

function find_longest_match(input, pos):
    best_offset = 0
    best_length = 0
    search_start = max(0, pos - WINDOW_SIZE)

    for i = search_start to pos - 1:
        length = 0
        while pos + length < len(input) and
              input[i + length] == input[pos + length] and
              length < MAX_MATCH:
            length += 1

        if length > best_length:
            best_length = length
            best_offset = pos - i

    return {offset: best_offset, length: best_length}
```

### Decoder

```
function lz77_decode(tokens):
    output = []

    for (offset, length, next_char) in tokens:
        if length > 0:
            start = len(output) - offset
            for i = 0 to length - 1:
                output.append(output[start + i])
        output.append(next_char)

    return output
```

## Parameters

### Window Size

Typical values:
- DEFLATE: 32 KB
- LZ4: 64 KB
- Zstandard: Up to 128 MB

Larger = better compression, more memory, slower search.

### Lookahead Size

Typical: 256 bytes to a few KB

### Minimum Match Length

Usually 3-4 bytes. Shorter matches may not save space after encoding offset/length.

---

## LZ77 in Practice

Direct LZ77 output is rarely used. Instead:

```
LZ77 → Tokens → Entropy Coding → Output

Examples:
- DEFLATE: LZ77 + Huffman
- Zstandard: LZ77 + FSE
- LZMA: LZ77 + Range coding + Markov models
```

---

## Key Takeaways

1. Uses sliding window as implicit dictionary
2. Output: (offset, length, next) tuples
3. Matches can overlap (copy into itself)
4. Finding matches efficiently is the key challenge
5. Usually combined with entropy coding
6. Foundation of gzip, PNG, ZIP, and more
