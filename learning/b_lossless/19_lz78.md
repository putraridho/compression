# Chapter 19: LZ78

## A Different Approach

While LZ77 uses a sliding window, LZ78 builds an **explicit dictionary** that grows during compression.

Published by Lempel and Ziv in 1978.

---

## The Core Idea

Instead of referencing positions in a window:
1. Build a dictionary of phrases
2. Output dictionary indices instead of offsets
3. Dictionary grows as new phrases are seen

---

## Dictionary Structure

The dictionary is a tree:

```
Root (empty string)
├── 'A' (index 1)
│   ├── 'B' (index 4)
│   └── 'C' (index 6)
├── 'B' (index 2)
│   └── 'A' (index 5)
└── 'C' (index 3)
```

Each node represents a phrase = parent's phrase + edge character.

---

## The Algorithm

### Encoding

```
1. Start with empty dictionary (just root at index 0)
2. Current phrase = empty
3. For each character:
   a. Extended phrase = current phrase + character
   b. If extended phrase in dictionary:
      - Current phrase = extended phrase
   c. Else:
      - Output (index of current phrase, character)
      - Add extended phrase to dictionary
      - Current phrase = empty
4. Output any remaining phrase
```

---

## Step-by-Step Example

### Input

```
"ABAABABAAB"
```

### Trace

```
Dictionary starts: {0: ""}

Char 'A':
  Extended: "" + 'A' = "A"
  Not in dict → Output (0, 'A'), Add "A" as index 1
  Dict: {0:"", 1:"A"}

Char 'B':
  Extended: "" + 'B' = "B"
  Not in dict → Output (0, 'B'), Add "B" as index 2
  Dict: {0:"", 1:"A", 2:"B"}

Char 'A':
  Extended: "" + 'A' = "A"
  In dict (index 1) → Current = "A"

Char 'A':
  Extended: "A" + 'A' = "AA"
  Not in dict → Output (1, 'A'), Add "AA" as index 3
  Dict: {0:"", 1:"A", 2:"B", 3:"AA"}

Char 'B':
  Extended: "" + 'B' = "B"
  In dict (index 2) → Current = "B"

Char 'A':
  Extended: "B" + 'A' = "BA"
  Not in dict → Output (2, 'A'), Add "BA" as index 4
  Dict: {0:"", 1:"A", 2:"B", 3:"AA", 4:"BA"}

Char 'B':
  Extended: "" + 'B' = "B"
  In dict (index 2) → Current = "B"

Char 'A':
  Extended: "B" + 'A' = "BA"
  In dict (index 4) → Current = "BA"

Char 'A':
  Extended: "BA" + 'A' = "BAA"
  Not in dict → Output (4, 'A'), Add "BAA" as index 5
  Dict: {0:"", 1:"A", 2:"B", 3:"AA", 4:"BA", 5:"BAA"}

Char 'B':
  Extended: "" + 'B' = "B"
  In dict (index 2) → Current = "B"

End of input, current = "B":
  Output (2, EOF) or just (2)
```

### Output

```
(0,'A') (0,'B') (1,'A') (2,'A') (4,'A') (2)

Indices: 0, 0, 1, 2, 4, 2
Chars:   A, B, A, A, A, -
```

## Decoding

```
1. Start with empty dictionary
2. For each (index, char):
   a. Look up phrase at index
   b. Output phrase + char
   c. Add phrase + char to dictionary
```

### Decode Example

```
Input: (0,'A') (0,'B') (1,'A') (2,'A') (4,'A') (2)

Dict: {0:""}

(0,'A'): "" + 'A' = "A"
         Output "A", Add dict[1] = "A"

(0,'B'): "" + 'B' = "B"
         Output "B", Add dict[2] = "B"

(1,'A'): "A" + 'A' = "AA"
         Output "AA", Add dict[3] = "AA"

(2,'A'): "B" + 'A' = "BA"
         Output "BA", Add dict[4] = "BA"

(4,'A'): "BA" + 'A' = "BAA"
         Output "BAA", Add dict[5] = "BAA"

(2): "B"
     Output "B"

Result: "A" + "B" + "AA" + "BA" + "BAA" + "B" = "ABAABABAAB" ✓
```

## Dictionary as Trie

Efficient implementation uses a trie:

```
struct Node {
    index: int
    children: Map<char, Node>
}

function find(phrase):
    node = root
    for char in phrase:
        if char in node.children:
            node = node.children[char]
        else:
            return null
    return node.index
```

Lookup is O(phrase length).

---

## LZ78 vs LZ77

| Aspect | LZ77 | LZ78 |
|--------|------|------|
| Dictionary | Implicit (window) | Explicit (tree) |
| Reference | (offset, length) | (index, char) |
| Memory | Window size | Unbounded growth |
| Long matches | Window-limited | Can be arbitrarily long |
| Implementation | Hash chains | Trie |

---

## Advantages of LZ78

1. **Unbounded phrases**: Can match very long patterns
2. **No window limit**: Old patterns stay in dictionary
3. **Fast lookups**: O(1) per character with hash/trie
4. **Simple output format**: Just (index, char) pairs

---

## Disadvantages of LZ78

1. **Unbounded memory**: Dictionary grows forever
2. **Dictionary overhead**: Must store or rebuild
3. **Patents**: Were patented (expired in 2003)
4. **Poor for some data**: Random data = huge dictionary

---

## Dictionary Management

### Maximum Size

Limit dictionary to N entries:

```
When full:
  Option 1: Stop adding (freeze)
  Option 2: Clear and restart
  Option 3: LRU eviction (complex)
```

### Transmission

Unlike LZ77, decoder can rebuild dictionary from output.
No need to transmit dictionary explicitly!

---

## Pseudocode

### Encoder

```
function lz78_encode(input):
    dict = {"": 0}
    next_index = 1
    current = ""
    output = []

    for char in input:
        extended = current + char

        if extended in dict:
            current = extended
        else:
            output.append((dict[current], char))
            dict[extended] = next_index
            next_index += 1
            current = ""

    if current != "":
        output.append((dict[current], EOF))

    return output
```

### Decoder

```
function lz78_decode(tokens):
    dict = {0: ""}
    next_index = 1
    output = ""

    for (index, char) in tokens:
        phrase = dict[index]

        if char != EOF:
            new_phrase = phrase + char
            output += new_phrase
            dict[next_index] = new_phrase
            next_index += 1
        else:
            output += phrase

    return output
```

---

## Comparison with LZW

LZW is a variant of LZ78 that:
- Outputs only index (no char)
- Initializes dictionary with all single characters
- Decoder needs special case for certain patterns

LZW became more famous due to GIF format.

---

## Key Takeaways

1. Builds explicit dictionary during compression
2. Dictionary is a trie of phrases
3. Output: (dictionary index, next character)
4. Decoder rebuilds dictionary identically
5. Unbounded memory usage without limits
6. Basis for LZW algorithm
